# TECHNICAL DESIGN — DESKTOP WEB JRPG

**Keputusan:** Phaser **4.2.1** + TypeScript + Vite (pin dependency pada Phase 0), dikerjakan di VS Code/IDE dan Claude Code. Target browser PC/laptop, terutama Chrome/Edge Windows, layar 16:9, keyboard, static hosting. Tidak ada Godot, GDScript, file `.exe`, autentikasi, cloud save atau server gameplay.

## 1. Kenapa stack ini

- Phaser adalah framework game 2D yang berjalan native di browser dan menerima input keyboard, kamera, tilemap, audio, dan animasi.
- TypeScript membantu sistem stat, quest, state-save, dan battle tidak berubah bentuk diam-diam saat AI mengedit kode.
- Vite memberi lokal dev server/hot reload serta build statis `dist`.
- Pilih **template resmi Phaser + Vite + TypeScript** tanpa React sebagai default. Jika Claude merasa perlu React, minta persetujuan terlebih dahulu; jangan memasang framework hanya untuk Settings/menu.
- Gunakan API dokumentasi Phaser **4**, bukan menyalin snippet Phaser 3 yang tidak diperiksa kompatibilitasnya. Kunci versi sebelum mengimplementasikan sistem.

## 3. Tanggung jawab subsistem

| Modul | Tugas | Dilarang |
|---|---|---|
| BootScene | initialize registry/settings, load minimal assets | mengambil foto privat dari server |
| TitleScene | New Game, Continue, **Settings**, Help/Controls | menjalankan save tersembunyi |
| WorldScene | player, tile collision, NPC, camera, encounter | menghitung damage battle |
| BattleScene | menampilkan aksi turn-based, HP/MP, feedback | menjadi sumber tunggal truth state |
| GameState | party, quest, inventory, stats, posisi, flags | menyimpan komponen Phaser yang tak serializable |
| SceneRouter | transisi menu/world/battle/cutscene, return point | stack scene tak selesai/duplikat |
| DialogueManager | data dialog ID, speed typewriter, choice | mengubah flags dari string dialog sembarang |
| BattleEngine | pure logic turn order/damage/reward | bergantung pada animasi untuk damage |
| SettingsRepository | master/BGM/SFX/text speed/fullscreen/scale/reduced effects | mengubah save story ketika setting diubah |
| SaveRepository | versioned save, validate, atomic-ish write/rollback | menganggap localStorage selalu tersedia |
| AudioManager | track ID, mute, volume groups, user-owned music slot | autoplay sebelum input user |
| AssetRegistry | logical ID → placeholder/final file | mengubah ukuran hitbox mengikuti PNG baru otomatis |

## 4. Render 16-bit yang konsisten

- Render 2D pixel art dengan nearest-neighbor. Resolusi internal **provisional** 320×180 atau 640×360 (keduanya 16:9), lalu fit fullscreen/desktop dengan letterboxing bila perlu.
- Pixel ratio/font ukuran skala diuji pada 1366×768 dan 1920×1080. Jangan biarkan ukuran CSS yang fractional membuat piksel blur; pilih integer zoom atau strategi snapping yang terbukti.
- Camera, world sprite, text overlay, UI DOM/Phaser tidak boleh punya skala yang bertabrakan.
- Untuk browser PC, target playback 60 FPS pada hardware normal, tanpa mengunci frame-based gameplay ke FPS; gunakan delta time.
- Browser viewport tetap 16:9; window lebih lebar/tinggi diberi matte letterbox yang estetis, bukan stretch.

## 5. Input keyboard dan fokus

**Draft layout:** arrows/WASD move, `Enter`/`Z` confirm/interact, `Esc`/`X` back/cancel, `Tab`/`Esc` pause/menu tergantung context, `F11` fullscreen browser via browser (opsi fullscreen in-app mengikuti persetujuan user dan permission). Semua intent melalui satu mapping, bukan hard-coded per-scene.

Urutan fokus: Modal Settings > Pause > Dialogue > Battle > World. Saat setting slider aktif, WASD tak menggerakkan karakter; tombol Esc menutup tepat satu layer. Tangani `window.blur`/tab background: pause movement, suspend audio bila perlu, jangan mengubah turn.

## 6. Browser storage

- Tidak perlu login/backend. Versioned save lokal: IndexedDB direkomendasikan untuk ukuran lebih besar, atau localStorage untuk save JSON kecil; jangan mengunci pilihan sampai tes target browser lulus.
- Settings kecil di localStorage dengan version `settings.v1`; fallback in-memory dengan notifikasi jika storage diblokir.
- Save (manual+autosave) punya slot berbeda, metadata timestamp + chapter + area + checksum ringan opsional. Jangan menggunakan save dari skrip lama secara membabi buta.
- Validate dan migrate schema; jangan memodifikasi state sampai payload lulus validasi.
- Refresh/tab close harus aman. Save hanya pada checkpoint stabil, bukan di tengah transisi / battle resolution / commit reward.
- Data situs terhapus = save hilang; UI harus menginformasikan risiko. **Export/import save JSON** boleh sesudah MVP jika direkomendasikan.

## 7. Public/private build dan deployment

- Game dapat di-host static HTTPS. Produksi `npm run build` → `web/dist/`; upload `dist` ke layanan host statis dan uji direct refresh/resource paths. Hosting tidak dilakukan otomatis tanpa instruksi.
- Asset private anniversary **tidak pernah masuk `dist` publik**. Menyembunyikan route dalam JavaScript tidak mengamankan gambar. Untuk versi pribadi gunakan build terpisah dengan file privat yang hanya diunggah jika user mengizinkan; kalau perlu akses tertutup, gunakan hosting yang benar-benar punya access control.
- Jangan tambahkan analytics, trackers, cookies marketing, atau upload file tanpa alasan dan izin.
- Karena target PC saja, tampilkan pesan informatif untuk viewport/perangkat kecil. Jangan mencoba menampilkan game mobile yang rusak.

## 8. Arsitektur event dan idempotensi

- NPC `npc_id` → `dialogue_id` dan optional structured event (bukan parsing kalimat bahasa Indonesia).
- `BattleEngine` menerima snapshot actor + encounter ID; hasil kemenangan adalah 1 transaction menuju GameState.
- `SaveRepository` tidak boleh menyimpan sprite instance/texture handle; yang disimpan ID, flags, stats, inventory, coords, chapter, quest.
- `CutsceneRunner` punya actions array, marker `on_skip`, idempotent milestone flags. Dua kali Enter tidak memberi item dua kali.
- Settings update real-time tanpa reload scene dan tanpa mengubah story save.

## 9. Testing wajib

1. `npm install` (atau `npm ci` setelah lockfile).
2. `npm run dev` dan buka lokal di desktop browser.
3. `npm run build` tanpa TypeScript error, lalu preview hasil build.
4. Unit test battle/save/quest/settings (misalnya Vitest, bila ditambahkan).
5. Browser smoke test keyboard (manual atau Playwright); user dapat mengubah Settings title/pause dan perubahan persisten setelah refresh.
6. QA pixel-art pada beberapa resolusi, frame rate dan transisi fullscreen.
7. Negative test: storage blocked, save corrupt, audio autoplay blocked, tab blur, mobile viewport.
